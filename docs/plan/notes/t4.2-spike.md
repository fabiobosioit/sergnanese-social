# T4.2 spike: tuttocampo.it widget findings

Date of spike: 2026-11-22. Method: one `curl` per widget (12 requests, about 2.5 s apart), User-Agent `SergneneseSocial-spike/0.1 (volunteer club tool; one-off check)`, no retries. Three extra Risultati requests to test URL parameters, and 64 HEAD requests to the image host (one per distinct ClubId seen in the Risultati widgets, 0.7 s apart). Raw HTML was kept outside the repo. Fixtures in `Tests/Fixtures/tuttocampo/` are sanitised (see the end).

## Summary and contradictions with the sheet

1. **Our ClubId is not 917410 everywhere.** Every club team has its own ClubId on tuttocampo.it. The six widgets give six different ones for "Sergnanese": 917410, 1032395, 1168472, 1283627, 1248872 and 1252673. The sheet's rule "a row is ours when a logo has ClubId 917410" only works for the first widget. Consequences:
   - `ClubSettings.tuttocampoClubID` (one value) is the wrong shape. The ClubId belongs to the team (next to the widget ID), or the "ours" test must be by team name "Sergnanese" plus the ClubId learned from the Classifica row.
   - Safer detection, which worked in all six widgets: the team name is exactly `Sergnanese`. The ClubId can be learned per widget from the Classifica widget (the row whose name is Sergnanese) and then stored on the team.
   - Opponent ClubIds are also per team: the same real club (for example one that plays in two of our leagues) has a different ClubId in different widgets. The same opponent club may therefore appear under several ClubIds. ClubId as "first matching key" for opponents is still valid inside one team, but an opponent shared across categories will not be recognised by ClubId alone.
2. **Date format has no year.** "Dom. 22 novembre". The year comes from the season in the URL (`?y=2026-27`, also in the `Squadra/` and `Partita/` links), so the parser must infer it (season 2026-27: August to December is 2026, January to July is 2027).
3. **A widget is a single matchday (Giornata), not the whole league calendar.** The default shows the current matchday of the league. Other matchdays can be requested with a path segment (below).
4. **Widgets do not say which category a team is.** Titles, captions and headings contain no league or category name. The mapping below is only a proposal based on opponents and match counts; the user must confirm it.
5. One widget (the sixth) returns the empty state for Risultati while its Classifica is filled.
6. Logos at `Teams/Original/<ClubId>.png` exist for every ClubId tested (64 of 64), but sizes go up to 1.08 MB, so the size cap must be generous (suggest at least 4 MB) or the fallback to the 80 px copy will be taken often.

## Request details

- `GET https://www.tuttocampo.it/WidgetV2/{Risultati|Classifica}/<id>` returns 200, `text/html; charset=utf-8`, 10 to 18 KB for results, 8 to 13 KB for rankings. No auth, no redirect.
- Response headers worth noting: `cache-control: no-store, no-cache, must-revalidate`, `set-cookie: PHPSESSID=...` (ignore it: use an ephemeral session or disable cookies), `access-control-allow-origin: *`, `x-mod-pagespeed` (the server rewrites markup, so structure can change).
- Encoding: UTF-8. No HTML entities appeared in team names in this sample, but `&amp;` appears in every `href` query string.
- The page contains Google Tag Manager and tuttocampo stylesheet links; none is needed for parsing and none must be loaded.

## URL parameters

- **Matchday: yes, as a path segment.** `/WidgetV2/Risultati/<id>/<N>?y=2026-27` (these are the links the page itself offers in the matchday strip). Tested on the first widget: `/10?y=2026-27` returned `<caption title="Risultati Giornata 10">` and the date "Dom. 15 novembre"; `/10` without `y` returned the same matchday (so `y` is optional and defaults to the current season).
- **Date query parameter: no effect.** `?d=2026-11-15` returned the default matchday (11) unchanged. Not worth further attempts.
- The matchday strip lists 9 matchdays: the 4 before and the 4 after the current one around the current one (7..15 around 11). This allows fetching next weekend's matchday if the current one is already played, but each extra matchday is an extra request.
- Classifica has no matchday strip.

## Matchday label

- In `table.table-results`: `<caption title="Risultati Giornata 11"></caption>`. The caption is empty, the text is in the `title` attribute.
- Also `<script>var currentMatchDay='11';var matchesNumber='30';var subPageName='Risultati';</script>` in the head. `matchesNumber` is the total number of matches in the league season (30 in the first widget), not the matches of the day. For the empty state `currentMatchDay='1'` and `matchesNumber=''`.
- The selected entry of the strip: `<div class="swiper-slide selected"><a href=".../11?y=2026-27"><span title="11">11</span>`.

## Date and time text

- Date header row: `<tr class="date"><td colspan="4"> ... <span>Dom. 22 novembre</span> ...`. Seen: `Sab. 21 novembre`, `Dom. 22 novembre`, `Dom. 15 novembre`. Pattern: abbreviated weekday with a dot (Sab., Dom.; other weekdays not seen, presumably Lun., Mar., Mer., Gio., Ven.), day number without a leading zero (not confirmed for days under 10), full lowercase Italian month name, no year. A header applies to the match rows that follow it until the next `tr.date`. A widget can carry two dates (Sat and Sun).
- Time: inside each match row, `<td class="match-time"><span class="hour" title=""><a ...>\n14:30 </a></span>`. Always `HH:MM` with a leading zero (`09:30`, `10:00`) and trailing space/newline. No time-less or "da definire" row was seen. The `title` attribute of `span.hour` was empty in all 32 rows.
- The time of a postponed match is still shown (the original time).

## Match status and score

Rows are `<tr class="match  ">` with extra classes for the state. Each team cell contains a `span.goal` with a `title` that carries the status. The score digit sits in the text of the span. Home first, away second, in the order of the cells.

| State | Row class | `span.goal` class and title | Score text |
|---|---|---|---|
| Scheduled | `match` | `goal` / "Partita da giocare" | `-` in both cells |
| Finished | `match` | `goal` / "Partita terminata" | digits, for example `8` and `4` |
| Live | `match live` | `goal live` / "Partita in corso (34')" or "Partita in corso (35+')" | current digits |
| Postponed | `match state-3` | `goal` / "Partita rinviata", and an extra `<a class="info" title="Partita rinviata"><span>Rinviata</span></a>` in the home cell | `-` in both cells |
| Suspended / abandoned / awarded | not seen | not seen | not seen |

In the 32 match rows seen: 14 scheduled, 10 finished, 5 live, 3 postponed. `state-3` = postponed is inferred from the one case seen; other numbers (suspended, awarded, cancelled) are unknown. The parser should treat any `title` it does not recognise as "needs review" rather than guess. The row class `selected` also appears on some of our rows (not all), probably highlighting the configured team; it must not be relied on.

## Markup of a match row

```
<tr class="match  ">
  <td class="match-time"><span class="hour  " title=""><a href=".../Partita/<code>?utm_..." class="ext_link">14:30 </a></span></td>
  <td class="team home ">
    <a href=".../Squadra/<ClubId>?utm_..." class="team-name ext_link">Name </a>
    <img class="hide_small" alt="logo Name" src='https://b2-content.tuttocampo.it/Teams/40/<ClubId>.png?v=1' srcset='.../Teams/80/<ClubId>.png?v=1 2x'/>
    <a href=".../Partita/<code>"><span class="goal " title="Partita da giocare">- </span></a>
  </td>
  <td class="team away "> (goal span first, then img, then name link: mirrored) </td>
  <td class="details">...INFO...</td>
</tr>
```

The tags are not closed consistently on one line and attributes use mixed quotes (`src='...'` single, `href="..."` double), so use a real HTML parser (SwiftSoup), not regexes. The home cell has the name first; the away cell has the name last. Names have a trailing space.

## Images

- Hosts: logos `b2-content.tuttocampo.it` (every team logo `src`, well over 100 of them); UI images `Web/Images/watermark.png`, `watermark5.png`, `icon_info.png`, resolved against the base (`b-static.tuttocampo.it`). The app must ignore the UI images.
- Every team logo `src` in the six Risultati and six Classifica widgets matches `https://b2-content.tuttocampo.it/Teams/40/<digits>.png?v=<1..9>`, with a `srcset` for `Teams/80/<digits>.png?v=<n> 2x`. No other size folder, no other extension, no other host was seen. The `v` value varies (1 to 9) and changes when the club updates its crest.
- `Teams/Original/<ClubId>.png` by HEAD: **64 of 64 ClubIds** (every distinct ClubId in the six Risultati widgets, including all five of our own that appear) returned 200 with `content-type: image/png`. `content-length` ranged from 14,640 bytes to 1,081,933 bytes (median about 187 KB). No 404 was seen, so the 40/80 fallback was never needed in this sample, but keep it. Pixel dimensions were not measured (HEAD only).
- Logos of our own team: 917410 and 1283627 have the identical size (118,998 bytes), probably the same crest uploaded twice. 1032395, 1168472 and 1248872 are 155 to 158 KB.

## Base href

Every page (all 12) has `<base href='https://b-static.tuttocampo.it/'/>` followed by an IE-only conditional comment. Relative URLs (`Web/Images/...`) resolve against it, not against `www.tuttocampo.it`. Team and match links are absolute `https://www.tuttocampo.it/2026-27/...`. If the parser resolves anything relative, use that base or, better, ignore relative URLs.

## Classifica widget (short)

`table.table_ranking`, rows `tr.promotion|playoff|...` (class varies by position; our row also has `selected`), cells: `td.team_logo > img`, `td.team > a` (name), `td.points.pt`, `pg`, `vt`, `pa`, `sc`, `gf`, `gs`, `dr`. Logo `src`s follow the same `Teams/40/<ClubId>.png?v=n` pattern. Useful to learn the team's own ClubId by the name "Sergnanese". Standings are not needed by the import itself.
